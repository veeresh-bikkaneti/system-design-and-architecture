### Seat C (Adversarial Skeptic), report, verbatim

VOTE: SUPPORT WITH CHANGES. The code is sound, but two findings should be resolved in the evidence packet before the vote becomes final. Verified means I read the source or the built dist/sw.js (built at the Pages base). I did not run a Cloudflare mirror build.

BLOCKING (acceptance conditions and evidence only, not code)
1. Navigation fallback hijacks static files. Verified, and the packet's "inferred" wording is wrong. vite.config.ts sets navigateFallback: '404.html' with no navigateFallbackDenylist. The built sw.js has NavigationRoute(createHandlerBoundToURL("404.html")) with no denylist. Once a worker controls a page, a navigation to /sitemap.xml, /feed.xml, /llms.txt, /robots.txt or /audio/* inside its scope returns the app shell. The scope is the base, so on the mirror at `/` this covers all of them; on Pages it covers only the course subpath. That includes the file-like paths the shell cannot serve, such as /oauth/callback and any worker API path on the same origin. The shell probably never serves a real asset, so I rate this a functional and SEO regression, not a confidentiality problem. Fix: add navigateFallbackDenylist: [/\.[a-z0-9]+$/i, /^\/auth\//] (or a base-aware equivalent), and change the packet from "inferred" to "verified". Rating this blocking is a judgment call: it changes an acceptance condition (feeds and sitemaps must stay fetchable), but the packet already documents it as a known deviation.
2. No recovery path from a broken deploy. Verified in src/main.tsx and sw.js. The built worker has cleanupOutdatedCaches and a message-driven skipWaiting, and no clientsClaim. If a deploy ships a bundle that crashes before UpdatePrompt renders, the user keeps the old precached app. They can reach the fix only through a registration update check, and that check is untested. Browsers byte-compare sw.js on navigation and bypass the HTTP cache for the script by default (inferred from the platform spec). Cloudflare and Pages cache headers for sw.js are UNVERIFIED, and there is no _headers file. The weaker failure is a new broken app that does install: the old worker stays until every tab closes, so a broken shell can persist. Minimum fix: either a one-line Cache-Control: no-cache for /sw.js plus a documented "ship a worker that calls self.registration.unregister() and skipWaiting" runbook, or ask the Chair to accept the risk in writing. The packet already flags this, so I rate it blocking only on that written acceptance.

NON-BLOCKING
3. T1 sync changes: no loss or double-apply found. applySnapshot no longer calls markClean (gist-sync.ts:36-42), and pushSnapshot marks clean with the pushed rev (:131). A failed push leaves the session dirty and retries later. The merge is idempotent, so I found no double-apply. Resurrection (R-07) depends on mergeProgress, which I did not trace. I did not check whether a dirty flag that stays set forever can occur.
4. Token handling is unchanged. The token stays in sessionStorage; no new storage of it and no logging in the diff. The worker has no runtime caching and the precache holds only JS, CSS and 404.html. Nothing replays offline. A 401/403 still leaves the token in sessionStorage (already the case). Continue navigates after a sync failure only when the token is still present.
5. Two bases are fine. Registration is `${BASE_URL}sw.js` with scope: base, so each origin has its own worker. The manifest uses relative `.` for start_url and scope, with no id. CI e2e runs at `/` only, so the subpath behaviour is untested, and the PR admits as much. Add one Pages-deploy smoke check.
6. CSP is unchanged. worker-src and manifest-src fall back to default-src 'self'.
7. Supply chain is clean. npm audit --omit=dev found 0 vulnerabilities. vite-plugin-pwa 1.3.0 is MIT and pulls in workbox-build 7.4.1. I did not look for install scripts in the 297 transitive packages (UNVERIFIED).
8. Precache is 13.4 MiB on first visit against a 20 MB gate. That is a data cost on mobile. Accept it and state it in the PR.
9. Privacy: no telemetry found. The manifest and worker add no third-party requests.
10. Scope. T-PWA-1..5 spans far more than the 3-file cap. The justification is recorded in the packet, but I did not compare it with the earlier T-PWA-4a/4b EVIDENCE_LOG.md entry.
