   `--only-missing` guard and corpus test are in the tree. Run
   `npm run test:tts` — expect all tests green (14 at F7a: 10 pre-existing +

2. Python venv per `scripts/tts/requirements.txt` (header, **verified** in repo):
   `cd scripts/tts && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`
   (CPU-only torch wheel; Kokoro 0.9.4). Plus the spacy `en_core_web_sm` model
   and `ffmpeg` on PATH (`synthesize.py` docstring, **verified** in repo).
3. Kokoro-82M weights cached: first run downloads from `hexgrad/Kokoro-82M`
   into `scripts/tts/.cache/hf/`; total cache ≈ 362 MiB, of which
   `kokoro-v1_0.pth` is 327,212,226 bytes (~312 MiB) (`scripts/tts/AUDIT.md` §5,
   **verified** there). `synthesize.py` SHA-256-verifies the weights against
   its pinned digest on every run and aborts on mismatch. For a hermetic run
   once cached: prefix commands with `HF_HUB_OFFLINE=1` (`synthesize.py`,
   **verified** in code).
4. Disk: keep at least ~1 GB free beyond the existing tree — **inferred**
   (confidence: likely) from the sourced figures below: ~313 MB of regenerated
   audio, ~362 MiB of model cache if not already present, plus per-lesson temp
   WAVs (streamed into `public/audio/<slug>-blocks-*/` and always cleaned up
   per lesson — `synthesize.py`, **verified** in code; the dir is gitignored).
5. Time: **UNVERIFIED** — no timed full run is recorded anywhere in the repo
   (searched `docs/`, `EVIDENCE_LOG.md`, `scripts/tts/AUDIT.md` on 2026-11-12).
   Synthesis is CPU-only with torch capped at 2 threads (`synthesize.py`,
   **verified** in code), so expect it to be long. Measure first: run step 3
   for ONE slug with `time`, multiply by 41 per voice, and decide before
   committing to the full run.

## The run (exact commands, from the repo root)

```bash
# 1. Re-extract narration scripts from the current MDX (all 41 lessons).
python3 scripts/tts/extract_narration.py

# 2. US voice (af_heart -> public/audio/<slug>/us/) — ALL 41 lessons.
#    NO --only-missing (see the warning at the top of this runbook).
HF_HUB_OFFLINE=1 scripts/tts/.venv/bin/python scripts/tts/synthesize.py --voice af_heart

# 3. UK voice (bf_emma -> public/audio/<slug>/uk/) — ALL 41 lessons.
HF_HUB_OFFLINE=1 scripts/tts/.venv/bin/python scripts/tts/synthesize.py --voice bf_emma

# 4. Validate every package against the player contract (82 runs).
for slug in $(ls content/lessons | sed 's/\.mdx$//'); do
  scripts/tts/.venv/bin/python scripts/tts/validate_manifest.py "$slug" us || echo "INVALID: $slug us"
  scripts/tts/.venv/bin/python scripts/tts/validate_manifest.py "$slug" uk || echo "INVALID: $slug uk"
done

# 5. Regenerate the narration index.
npm run narration:index
```

If a run fails partway, re-running the same command re-synthesises everything
for that voice (safe, just slow). `--only-missing` is acceptable ONLY as a
retry for lessons a failed run actually missed — and the guard now prints how
many it skipped and refuses (exit 2) if it would skip everything.
